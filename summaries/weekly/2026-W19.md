### Highlights

This week, Galaxy project work centered on three themes: event preparation, tool and format improvements, and internal code cleanup. The training-material repository added new track pages and schedules for GTA 2026 sessions covering Single Cell, Microbiome, and Digital Humanities, while several tutorial fixes were merged. The main Galaxy server repository received dependency updates, bug fixes for SQL compatibility and MCP serialization, and frontend refactoring that replaced older components with a unified loading spinner and a Pinia-based quota store. Across other repositories, tools-iuc added two new tools and updated several existing ones, gxformat2 improved how Format2 workflow definitions convert to Galaxy's native format, and the newly renamed Loom repository was reorganized with updated documentation and fixes for agent tooling.

## Repository Summaries

### chatgxy-materials
A pull request was merged that added a Galaxy documentation MCP (Model Context Protocol) component and fixed the chunking process used for the E5-Mistral model. This was the only change to the repository this week.

### usegalaxy-tools
This week, the usegalaxy-tools repository received several routine tool repository updates (on May 6 and May 9), along with the addition of missing Gemini tools, updated GLEAM tool revisions for usegalaxy.org, and installation of IWC tools for the cloud platform. Two new issues were opened reporting suspected configuration problems with fastp 1.3.3+galaxy0 and msconvert 3.0.20287.7 on usegalaxy.org.

### galaxy
This week, the Galaxy repository merged fixes for SQL compatibility in message pruning, an MCP crash on dataset detail serialization, and missing TLS support for FTP in configuration templates. Several dependency updates were applied (python-multipart, mako, axios, mistune, and slackapi/slack-github-action), and frontend code was cleaned up by standardizing on a unified loading spinner component and replacing the quota usage provider with a Pinia store. New issues filed this week include bugs around data source tools getting stuck, workflow extraction missing intermediate steps, tool panel errors when login is required, and a database transaction error, along with feature requests for canceling workflow invocations on specific tool failures and adding convenience data mapping files to exported histories.

### galaxy-language-server
A single dependency update was merged this week: the `fast-uri` package used in the client was bumped from version 3.1.0 to 3.1.2.

### gxformat2
This week, the gxformat2 repository received six merged pull requests focused on improving how Format2 workflow definitions are converted to Galaxy's native format. Changes included propagating step input defaults and step-level post_job_actions during conversion, accepting additional shorthand syntax for multi-source inputs and integer `$link` values, fleshing out workflow input fields in the schema, clarifying input type aliases, and fixing integer step key handling in native workflow loading.

Nine new issues were opened covering topics such as schema support for restrictions and suggestions, support for additional native Galaxy input types (color, directory_uri), and proposals to gate new shorthand syntax behind feature flags. Four of those issues were closed within the week, addressed by the merged pull requests.

### loom
This week, the Loom repository was renamed and cleaned up: references to "pi-galaxy-analyst" were renamed to "loom," the orphaned `galaxy-claw/` directory was removed, and `AGENTS.md` was split into separate docs under `docs/agent/*` with a new session-end protocol. On the tooling side, a workaround was added for LLMs hallucinating Unicode-confusable tool names (fixing a newly filed and closed issue), BRC Analytics MCP was bundled alongside galaxy-mcp, and npm dependencies were updated to resolve vulnerabilities. Thirteen issues were closed spanning Orbit UI improvements (file previews, entry counts, stop-button subprocess handling, liveness indicators, model-switch prompts, and preferences behavior), credential handling, agent prompt adjustments, and test infrastructure, while three new issues were opened covering local Pulsar-based job execution, auto-configuration of

### training-material
This week's work on the training-material repository focused heavily on preparing for the GTA (Global Training Alliance) 2026 event, with new track pages and schedule links added for Single Cell, Microbiome, Digital Humanities, and related sessions. Several tutorial fixes were also merged, including a typo correction, a duplicated contributor entry removal, an update to a Chinese tutorial's sort tool availability, and a dataset import workflow now illustrated with a gif. Open issues flagged outstanding problems for the Machine Learning and Climate tracks, including broken data links and needed tutorial fixes, as well as a high-priority Conda issue on the French Galaxy instance.

### tools-iuc
This week, the tools-iuc repository received several tool version updates (staramr, obitools, fastreer, metabat2) and two new tools were added: a page dewarp tool and jdeskew. Multiple PRs addressed linter fixes across various tools (allegro, biom format, add name, mapseq), and the raxmlng tool was refactored to consolidate version information into macros. A GitHub Actions dependency (SimenB/github-actions-cpu-cores) was also bumped from version 2 to 3.

### planemo
A documentation typo was fixed in the Planemo repository this week. No other changes were merged.

### kui
One new issue was opened reporting that dataset counts are inflated, and one issue regarding a syntax error was closed. Overall, the repository had minimal activity this week with just these two issue-related changes.

### galaxy-hub
A new page was added for a Galaxy Single-cell & Spatial Analysis community meeting in May. Additionally, files were synced from the Galaxy Training Material repository to keep the hub up to date.

### galaxy_codex
One pull request was merged this week, updating the annotation configuration file to include the TSI pipeline and Fgenesh v4. Three issues were closed: one about tools missing from generated TSV files despite their category being included, one about SQL queries for tool usage counting deleted jobs, and one about broken tool links in Labs.

### jxtx
A pull request was merged to add an announcement for the 2026 Biology of Genomes (BOG) scholarship awardee to the JXTX Foundation repository. This was the only change made to the repository this week.

### gravity
A new abstract method `is_ready()` was introduced in a `RollingRestartableService` subclass. A bug was reported where gravity version 1.2.0 and above throws an exception during graceful restarts, failing to restart handlers; this issue was subsequently closed within the same week.

### brc-analytics
This week, a new issue was opened proposing to add BRC datasets to the Google Datasets catalog, which would make the project's datasets discoverable through Google's dataset search. No other activity was recorded in the repository during this period.

### pulsar
This week, one pull request was merged that changes sudo calls in Pulsar to return their standard output as a string. A new issue was opened requesting documentation for a local relay-based setup and fixes for single-core default behavior and shared-password authentication. One older issue about disabling conda auto-initialization was closed.
